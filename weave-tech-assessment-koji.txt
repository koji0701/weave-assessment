⏺ Here's how it currently works:

  The query: Line 60 fetches ALL closed PRs sorted by updated_at descending —
  repo.get_pulls(state="closed", sort="updated", direction="desc"). This is a
  lazy paginated iterator (100 per page via per_page=100), so it doesn't
  download all tens of thousands at once, but it does iterate through them.

  The stop condition: Line 66 — if pr.updated_at < cutoff: break. It stops when
  it hits a PR whose updated_at is older than days ago. With the current days
  parameter, that's the cutoff.

  The problem: PostHog/posthog is extremely active. Even with a 30-day window,
  the updated_at sort means it has to page through every closed PR that was
  updated in that window — not just merged. A PR opened a year ago that got a
  comment yesterday would still appear. So the iterator touches far more PRs
  than it keeps.

  Per-PR cost: For every qualifying PR (lines 67-90), it also calls
  pr.get_reviews() (line 93) — that's a separate API call per PR. So if 500 PRs
  qualify, that's ~500 list pages + ~500 review calls = ~1000+ API requests.

  No hard cap: There's no max limit on the loop. It just keeps going until
  updated_at < cutoff.

  With your slider now at 3–30 days max, the volume is much more manageable, but
   it's still potentially hundreds of PRs given PostHog's activity level. Want
  me to plan any changes to further limit this, like adding a hard cap on PR
  count?
